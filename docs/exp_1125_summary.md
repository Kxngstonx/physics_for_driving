## 1. 용어 (헷갈리기 쉬운 것)

### 학습 모델 vs 시뮬레이터
- **학습 모델** (R1–R6, N1·N2·N5): 실제 주행 기록(D7)으로 "지금 상태 + 조작 → 0.04초 뒤 속도 [vx, vy, r]" 를 맞히도록 학습한 모델. 학습할 때 시뮬레이터는 쓰지 않는다.
- **시뮬레이터** (P2): MPPI 주행 시험에서 "실제 차" 역할을 하는 식. 계수만 데이터로 맞추고 학습 모델과는 따로 있다.

### P1 과 P2 (둘 다 자전거 모델 = 앞바퀴 둘, 뒷바퀴 둘을 하나씩으로 합쳐 본 차)

| | P1 | P2 (지금 시뮬레이터) |
|---|---|---|
| 타이어 옆 힘 | 미끄러질수록 커지다 한계에서 멈춤 (Pacejka) | 같음 |
| 타이어 한계 | μ × 정지 상태 바퀴 하중 (고정) | μ × **그 순간의** 바퀴 하중 |
| 앞뒤 무게 이동 | 없음 | 있음 (제동하면 앞이 눌려 앞 타이어 한계가 커짐) |
| 마찰원 | 없음 | 있음 (제동·가속에 마찰을 쓴 만큼 옆으로 버틸 힘이 줄어듦) |

P1 은 저장소에 구현되어 있지 않다. 학습 모델 안의 물리 식으로 보면 R1–R4 는 P1 수준, R5·R6 은 물리 없음, N1·N2·N5 는 P2 식이다 (3절).

주의: 시뮬레이터도 P2 라서, 같은 식을 쓰는 N 모델이 주행 시험에서 구조적으로 유리할 수 있다. 다른 세계(팀원 시뮬레이터)에서도 돌려 확인해야 한다.

### 개루프 평가 (모델 순위를 정한 방법)
시험 파일(10_1, 11_1, 11_5)에서 0.2 s 마다 시작점을 잡고(1337개), **기록된 조작을 그대로 넣어** 모델을 1초(25스텝) 굴린 뒤 실제 속도와의 RMSE 를 잰다. 위치가 아니라 **속도(vx, vy, r) 오차**다. 팀원 `evaluate.py` 그대로.

### 계획 길이 (MPPI 주행 시험에서만 나오는 값)
MPPI 는 0.04 s 마다 "앞으로 1초 이렇게 밟고 꺾으면?" 후보 1024개를 학습 모델로 굴려 보고, 좋은 후보를 섞어 첫 0.04 s 조작만 쓴다. 이 "앞으로 몇 초" 가 계획 길이다.
- 팀 결정은 1초 (회의 11/17). 길게 보면 제어기가 모델의 부족함을 덮어 모든 모델이 완주하고 차이가 사라진다.
- 학습에는 MPPI 가 들어가지 않는다. 다만 학습 손실을 1초(25스텝) 굴림 오차로 잡은 것(`--roll 25`)은 MPPI 가 모델을 1초 굴려 쓰기 때문이다.

### MPPI A 방식 / B 방식

| | A 방식 | B 방식 |
|---|---|---|
| 목표 | 기록 주행선 + 다른 실제 랩(10_5)의 위치별 속도를 따라감 | 목표 없이 트랙 경계 안에서 최대한 전진 |
| 팀원 결과 (11/19, 계획 1초, CommonRoad 세계) | λ 0.3 에서 6개 모델 모두 완주 (+1.8~2.7%) | 54회 모두 실패 (진행률 2~70%) |

## 2. 공통 학습 조건

- 데이터: **D7 만** (학습 14 / 검증 3 / 시험 3 파일, 팀원 분할: 검증 11_4·11_7·11_8, 시험 10_1·11_1·11_5). D1 은 쓰지 않았다.
- 설정: `GOLF_THUNDERHILL_G` (m 1496.9 kg, 앞 제동 몫 0.75, Fxf = 0.699·구동 − 앞 제동, 종경사 입력, 좌우 기울기 0, dt 0.04 s).
- 입력: 과거 8스텝(0.32 s)의 [vx, vy, r, Fxf, δ, bank, grade] → 출력: 0.04 s 뒤 [vx, vy, r].
- 학습 규칙 (`train.fit`, 모든 모델 같음): 25스텝(1초) 이어 굴린 오차를 손실로 (k번째 스텝 가중 1/k, 1스텝 변화량 표준편차로 나눔), Adam 학습률 1e-3 (물리 계수는 3배), 배치 1024, 검증 손실이 10 에폭 안 줄면 학습률 ½, 25 에폭 안 줄면 멈춤, 최대 300 에폭, 검증 최저 모델 저장. 시드 0·1·2.
- 학습 전 점검: `python experiments/golf/check_train_setup.py` (21개 항목, 모두 통과).
- 학습 장소: R3 는 Colab GPU, 나머지는 로컬 CPU (작은 모델이라 GPU 가 오히려 느림: 계산보다 GPU 호출 대기 시간이 큼).

## 3. 모델 설명

모든 모델은 같은 형식(hist (B, 8, 7) → 다음 [vx, vy, r])이라 학습·평가·MPPI 코드를 그대로 쓴다. R1–R6 은 팀원 `deep_dynamics/golf/ladder.py`, N 모델은 `deep_dynamics/golf/hybrid.py`.

### 물리 뼈대 두 가지

| | R 물리 식 (R1–R4) | P2 물리 식 (N1·N2·N5) |
|---|---|---|
| 차 모형 | 자전거 모델 | 자전거 모델 |
| 타이어 옆 힘 | Pacejka, 앞·뒤 축마다 **고정** 최대 힘 Df, Dr | Pacejka, 최대 힘 = **μ × 그 순간의 축 하중** |
| 앞뒤 무게 이동 | 없음 | 무게중심 높이 h 로 계산 |
| 마찰원 | 없음 | 앞뒤로 쓴 힘만큼 옆 힘 최대치 감소 |
| 저항·경사 | 굴림 + 공기 저항, −g·sin(경사) | 같음 |
| 적분 | 오일러, 0.04 s 를 4번 | RK4, 0.04 s 를 2번 |
| 계수 | 13개: Pacejka 8개(Bf Cf Df Ef Br Cr Dr Er), 저항 2개, Iz, kb, ds | 11개: a, Iz, 강성 cf·cr, 모양 Cf·Cr, μ, h, 저항 c0·c2, ds |

ds 는 속도 센서 위치(무게중심 앞 몇 m)다. vy 를 센서 위치 ↔ 무게중심으로 바꿀 때 쓴다.

### 모델별

| 모델 | 한 줄 설명 | 구조 | 학습하는 것 | 파라미터 수 |
|---|---|---|---|---|
| **R1** 순수 물리 | 물리 식 하나로 전부 | R 물리 식 | 계수 13개 (데이터 전체에 하나) | 13 |
| **R2** 물리+잔차 | 물리 예측에 신경망이 "틀린 만큼" 더함 | R1 결과 + MLP(이력 8스텝, [64,64]) × 1스텝 변화량 크기. 마지막 층 0 시작 → 처음엔 R1 | 계수 13개 + MLP | 8,016 |
| **R3** 신경망 타이어 | 물리 식에서 타이어만 신경망 | R 물리 식, 앞·뒤 타이어 옆 힘만 MLP(미끄럼각, 속도 → 힘, [32,32], 좌우 대칭 = 홀함수, 최대 힘도 학습) | 저항·Iz 등 + 타이어 MLP 2개 | 2,385 |
| **R4** DD식 계수추정 | 매 순간 신경망이 물리 계수를 새로 고름 (Deep Dynamics 논문 방식) | MLP(이력, [128,128]) → 범위 안의 계수 13개 → R 물리 식 | MLP | 25,485 |
| **R5** Stanford식 NN | 물리 없이 신경망이 변화량을 예측 (Spielberg 2019) | 다음 = 현재 + MLP(이력, [128,128]) × 1스텝 변화량 크기 | MLP | 24,195 |
| **R6** 블랙박스 | 신경망이 다음 상태를 바로 예측 | 다음 = MLP(이력, [128,128]) (표준화 공간) | MLP | 24,195 |
| **N1** P2 물리 | R1 의 물리 식을 P2 식으로 바꿈 | P2 물리 식. 계수 초기값 = P2 시뮬레이터 피팅값 | 계수 11개 | 11 |
| **N2** P2 + 힘 보정 | N1 에 신경망 보정을 "힘(가속도)" 자리에 넣음 | MLP(이력, [64,64]) → 보정 가속도 [Δax, Δay, Δṙ], P2 미분 식 안에 더해 RK4 로 적분. 마지막 층 0 시작 → 처음엔 N1 | 계수 11개 + MLP | 8,014 |
| **N5** R5 + P2 물리 | P2 예측 + R5 크기 신경망 보정. 신경망이 물리 예측도 봄 | 다음 = P2(현재) + MLP([이력, (P2 − 현재)/변화량 크기], [128,128]) × 변화량 크기. 마지막 층 0 시작 → 처음엔 N1 | 계수 11개 + MLP | 24,590 |

새 모델을 만든 이유 (가설)
- N1: 물리 뼈대가 실제 차에 가까우면(무게 이동, 마찰원) R1 보다 낫다.
- N2: R2 는 다음 상태에 보정을 직접 더한다. 힘 자리에 더하면 보정이 물리 적분을 거쳐 단위·크기가 자연스럽다 → R2 보다 낫다.
- N5: R5(신경망만)가 vx·vy 에 강하고, 물리가 있는 R2·N2 가 r 에 강했다. 둘을 합치면 둘 다 잡는다. 신경망 입력에 물리 예측을 넣어 "물리가 틀리는 상황"을 보고 고치게 했다.

설계 문서: [`new_model_1125.md`](new_model_1125.md).

### 4-8. 해석

1. **N5 가 가장 좋은 모델이다 (조건부).** 1초 vx 는 R5 보다 2%, r 은 R2 보다 4% · R5 보다 15% 낮다. vy 는 R5 가 3% 낫다. 출발 구간을 빼도, 앙상블로 해도 같은 순위.
2. **차이는 작다.** N5 와 R5 의 vx 차이(0.003)는 시드 간 표준편차(0.002~0.003)와 비슷하다. vx·vy 는 "R5 와 동급", r 은 "확실히 더 좋음" 으로 읽는 게 맞다.
3. **물리 뼈대는 r(회전) 에 효과가 있다.** 물리가 있는 모델(R2, R4, N2, N5)이 r 에서 물리 없는 R5·R6 보다 낫다. vx·vy 는 신경망 크기가 큰 쪽(R5, N5)이 낫다.
4. **P2 식만으로는 부족하다.** N1(0.255)은 R1(0.269)보다 vx 는 조금 낫지만 r 은 더 나쁘다(0.042 vs 0.039). 신경망 보정이 있어야 P2 뼈대의 장점이 나온다.
5. **N2 vs R2:** 힘 자리에 보정(N2)이 상태에 보정(R2)보다 vx·vy 가 조금 낫고 r 은 같다. 차이는 시드 편차 수준.
6. **계산 시간이 단점이다.** 후보 1024개·한 스텝 CPU (11/26, 학습 4개를 같이 돌리는 중에 잼): R5 6.9 ms, R2 12.6, N2 19.3, **N5 23.1**. 즉 N5 는 R5 의 약 3.3배, N2 의 1.2배. (11/25 에 부하 없이 잰 값은 R5 2.1, R2 5.7, N2 12.7 ms.) GPU·MPPI 에서 다시 잰다.
7. **주의:** P2 시뮬레이터로 주행 시험을 하면 P2 식을 쓰는 N 모델이 유리할 수 있다 (1절). 개루프 평가는 실제 데이터라 이 문제가 없다.
