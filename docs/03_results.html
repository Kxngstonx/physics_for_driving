Deep Dynamics 수정과 재현 결과

2부의 문제를 고친 내용, 수정 전후로 시드를 바꿔 가며 학습·평가한 결과, 그리고 후속 조사를 정리합니다.

수정한 내용 실험 구성 AV-21 결과 Bayesrace 결과 해석할 때의 주의 후속 조사 복원된 테스트 구간은 학습 범위 밖의 속도다 ω 최대 오차의 원인 Bayesrace가 논문 수치에 미치지 못하는 이유 무작위 분할은 의도된 동작인가

2부의 문제 중 합의된 항목을 고친 뒤, 수정 전 코드와 수정 후 코드로 각각 학습·평가해 논문 수치와 비교했습니다. 모델은 Deep Dynamics만, 하이퍼파라미터는 논문 값(Bayesrace 배치 2 / LR 0.000144, AV-21 배치 64 / LR 0.001914), 400 epoch, 시드 5개입니다.

실험 구성

수정 전 코드와 수정 후 코드를 각각 시드 5개(0–4)로 학습했습니다. 표의 값은 시드 5개의 평균 ± 표준편차입니다. 수정 전 코드에는 시드 옵션이 없어, 코드를 고치지 않고 실행 직전에 난수 생성기를 고정하는 래퍼(experiments/seeded_run.py)로 돌렸습니다. 논문은 시드나 반복 실행을 언급하지 않고 값 하나만 보고하므로 참고 값으로 함께 적습니다.

해석할 때의 주의

  • 논문과 같은 데이터가 아닙니다. 논문의 표본 수(학습 13,418, 테스트 10,606)는 현재 변환기로 나오는 수와 다릅니다. 변환기의 속도 임계값이 커밋마다 바뀌어 왔으므로 논문이 쓴 구간을 정확히 복원할 수 없습니다.
  • 시드 5개는 큰 차이만 가려냅니다. 평균 차이가 표준편차의 1–2배 이내인 항목은 "차이 없음"이 아니라 "이 횟수로는 판단 불가"로 읽어야 합니다. p 값은 참고용입니다.
  • 수정의 가치는 평균 성능이 아니라 평가의 신뢰성에 있습니다. 수정 후에는 테스트 로그 전체로 평가하고, 검증이 학습 데이터와 겹치지 않으며, 같은 시드로 결과가 재현됩니다.
  • 원본 롤아웃 스크립트의 자세 정렬. visualize/plot_predictions_iac.py는 시작 위치를 윈도 첫 행에서, 시작 속도를 윈도 마지막 행에서 가져옵니다. 이 방식으로 계산하면 AV-21의 ADE가 약 7% 크게 나옵니다. 표의 AV-21 값은 같은 행으로 맞춘 값입니다.
  • evaluate.py의 메모리 사용. 원본은 그래디언트 추적을 끄지 않아 LVMS 전체를 평가할 때 3.5 GB 이상을 씁니다. torch.no_grad()를 넣어 1.5 GB로 줄였고 수치는 동일합니다.
  • 재현 방법. experiments/reproduce.sh(data, SEED=n fixed, SEED=n baseline), experiments/evaluate_orca_paper.sh, experiments/summarize.py 순으로 실행합니다. experiments/limited.sh로 감싸면 메모리 상한 안에서 돕니다. 시드별 로그와 집계는 experiments/results/에 있습니다.

후속 조사

시드 반복 실험에서 나온 세 가지 의문을 추가 분석과 추가 학습으로 조사했습니다. 추가 학습은 모두 메모리 상한 안에서 실행했습니다.

복원된 테스트 구간은 학습 범위 밖의 속도다

수정 전 모델을 LVMS 전체로 평가했을 때 오차가 커진 것은 이 때문입니다. 수정으로 모델이 나빠진 것이 아니라, 평가가 더 어려운 구간까지 넓어졌습니다.

ω 최대 오차의 원인

큰 ω 오차는 고속 구간이 아니라, 신경망이 계수를 Physics Guard 범위의 끝값으로 내보내는 극소수 윈도에서 나옵니다.

  • 위치. 수정 후 시드 0, 1, 3의 최대 오차는 세그먼트의 처음 몇 개 윈도(속도 약 7 m/s, 5 m/s를 막 넘은 출발 구간)에서 나옵니다. 45 m/s 이상 구간의 ω 최대 오차는 0.02–0.19입니다.
  • 계수. 가장 나쁜 윈도에서 수정 후 모델은 Bf 30, Cf 2, Df 9,739, Dr 9,997, Iz 502를 냈습니다. 모두 허용 범위의 끝값이라 타이어 힘은 최대, 관성은 최소가 되고 ω 변화가 과대 예측됩니다. 같은 윈도에서 수정 전 모델은 Iz 1,992를 냈고 오차는 0.001이었습니다.
  • 빈도. Iz가 600 미만인 윈도는 테스트의 0.01–0.1%이고, 학습 데이터에서는 수정 전·후 모두 0%입니다. 다른 트랙에서만 드물게 나타납니다. 이 윈도를 빼면 수정 후 시드 0, 1의 ω RMSE는 0.009, 0.005입니다.

  • 수정 때문에 나빠진 것이 아닙니다. 수정 전 15회와 수정 후 5회 사이에 구분되는 차이가 없습니다(모든 항목 p ≥ 0.45). 무작위 분할과 시간 블록 분할 사이도 5회로는 구분되지 않습니다(p ≥ 0.30).
  • 수정 전 코드로는 15회 중 한 번도 논문 값에 닿지 못했습니다. 가장 좋은 실행도 vx RMSE 4.4e-5로 논문의 약 3배입니다. 전체 30회 가까운 실행 중 논문의 vx RMSE와 ADE에 닿은 것은 한 번(수정 후 코드, 무작위 분할, 시드 1)입니다.
  • 테스트 오차는 학습 범위 밖 윈도가 결정합니다. 테스트 윈도의 28.8%(287개)에 학습 트랙에 없던 입력이 있습니다. 테스트 파일에서 피처로 쓰이는 Euler 적분 궤적이 헤어핀 두 곳에서 실제 시뮬레이션 궤적과 갈라져 스핀하기 때문입니다(속도 −1.67 m/s, ω −19 rad/s. 같은 시점의 실제 궤적은 0.86 m/s). 범위 안 윈도의 ω RMSE는 0.001–0.024로 학습 트랙에서의 값과 같고, 범위 밖 윈도는 0.04–0.17입니다. 이 구간의 성능은 외삽이라 시드마다 크게 달라집니다.
  • 트랙을 바꾸면 ω RMSE가 100배 낮아집니다. ETHZMobil로 학습하고 스핀 구간이 없는 ETHZ로 테스트하면 0.0006입니다.
  • 배제한 원인. 오차 하한은 0입니다(정답 계수를 넣으면 RMSE가 정확히 0). 저장소 YAML의 하이퍼파라미터로 돌려도 같은 범위입니다. 한 실행 안에서 테스트 기준 최선의 체크포인트를 골라도 vx RMSE가 최대 2배 줄 뿐입니다.
  • 남는 설명. 논문 값은 여러 시도 중 드물게 나오는 좋은 실행이거나(저자의 튜닝은 200회 시도, 논문은 테스트셋을 검증에 썼다고 서술), 논문이 쓴 데이터 파일이 저장소의 파일과 다를 가능성이 있습니다. 둘 다 확인할 방법이 없어 추정으로 남깁니다.

학습 배치의 순서를 섞는 것은 표준 관행이고 문제가 아닙니다. 문제가 되는 것은 겹치는 윈도를 학습과 검증(또는 테스트)에 무작위로 나누는 것입니다.
