## 1. 한 줄 요약과 목표

신경망 차량 모델은 짧은 예측에서 앞서지만, 한계 주행에서는 물리를 남긴 모델이 더 버틴다는 것을 보이는 프로젝트다.

- Thunderhill에서 수집한 VW Golf 한계 주행 데이터로 차량 모델 6종(R1–R6)을 학습한다.
- 각 모델을 MPPI 제어기에 넣고 시뮬레이터에서 주행시켜 비교한다.
- 평가 기준은 1순위 완주 여부, 2순위 랩타임이다. 학습에 쓰지 않은 트랙에서도 검증한다.
- 발표는 12/30이다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 한계 주행 | 타이어 접지력을 거의 다 쓰는 주행. 미끄러지기 직전이거나 이미 미끄러지는 상태 |
| 개루프 평가 | 기록된 데이터에서 모델이 다음 상태를 얼마나 맞히는지 보는 평가 |
| 폐루프 평가 | 모델을 제어기에 넣고 시뮬레이터에서 차를 직접 몰게 해 완주 여부와 랩타임을 보는 평가 |
| MPPI | 무작위 조작 후보를 많이 굴려 보고 비용이 낮은 쪽으로 조작을 정하는 제어 방식 |
| 계획 길이 | MPPI가 몇 초 앞까지 내다보는지 |
| R1–R6 | 비교하는 차량 모델 6종. R1 순수 물리, R2–R4 물리+신경망, R5–R6 신경망 |
| 상태 | 모델이 예측하는 값 `[vx, vy, r]`. vx 전진 속도, vy 옆 방향 속도, r 회전 속도(요레이트) |
| 1스텝 손실 | 실제 기록을 넣고 0.04초 뒤 하나만 맞히게 하는 학습 방식 |
| 1초 손실 | 모델이 자기 예측을 다시 입력으로 쓰며 25스텝(1초)을 굴리고, 그 전체를 맞히게 하는 학습 방식 |
| 에폭 | 학습 데이터 전체를 한 번 보는 단위 |
| 시드 | 무작위 수의 출발값. 같은 시드면 같은 결과가 나온다 |
| 저역 통과 필터 | 신호에서 빠르게 흔들리는 성분을 지우고 느린 성분만 남기는 처리 |
| 에일리어싱 | 데이터를 듬성듬성 뽑을 때, 빠른 흔들림이 느린 가짜 신호로 섞여 들어오는 현상 |
| 미끄럼각 | 바퀴가 향한 방향과 실제로 움직이는 방향의 차이 |
| 하중 이동 | 가속·제동·선회 때 바퀴마다 실리는 무게가 달라지는 현상 |
| 액추에이터 | 조향 모터, 엔진, 브레이크처럼 명령을 실제 움직임으로 바꾸는 장치 |
| 감속비 | 엔진 회전 속도 ÷ 바퀴 회전 속도. 기어에 따라 바뀐다 |
| RMSE | 오차를 제곱해 평균한 뒤 제곱근을 취한 값. 오차의 대표 크기 |
| RLS | 재귀 최소제곱법. 데이터를 차례로 받으며 계수를 갱신해 맞추는 방법 |
| ablation | 요소 하나만 바꿔 그 영향을 보는 보조 실험. 주 실험(main)과 구분한다 |
| grid search | 설정값 후보들의 모든 조합을 돌려 보는 탐색 |

## 3. 전체 흐름

1. Golf 데이터를 받아 중복을 지우고 로더를 새로 만든다.
2. 차량 제원을 데이터로 추정한다. 추정 방법은 제원을 아는 차(GTI, AV-21)로 먼저 검증한다.
3. R1–R6을 학습하고 개루프 예측 오차를 비교한다.
4. 시뮬레이터(CommonRoad 다물체 모델)를 Golf에 맞추고 검증한다.
5. 썬더힐에서 MPPI 두 방식(A, B)과 grid search로 폐루프 주행을 비교한다.
6. 최종 평가 트랙(미정)에서 일반화 성능을 본다.

3번까지는 시뮬레이터가 필요 없다. 5번부터 필요하므로 4번은 최종 평가보다 먼저 끝나야 한다.

## 4. 결정 사항과 이유

### 4-1. 데이터

| 결정 | 이유 |
|---|---|
| 데이터는 Golf(purl.stanford.edu/hh613qz0317)만 쓴다. ver2 코드의 GTI 기준은 버린다 | 회의 결정이 기준이다. ver2 코드는 다른 차인 GTI의 데이터(zb950hd3384)와 제원을 쓰고 있었다 [확인: `ladder_models/thunderhill_data.py:3`, `configs.py:38-46`] |
| 중복 파일 2개를 지워 20개로 정제한다 | `2023-10.csv` = `2023-10_2.csv`, `2023-10_1.csv` = `2023-10_3.csv`. Stanford가 공개한 MD5·SHA1이 같다 [확인]. 두면 같은 주행이 학습과 시험에 함께 들어갈 수 있다 |
| 사람이 몬 구간과 자동 운전 구간을 모두 쓴다. "사람만" ablation은 하지 않는다 | 사람 구간만 쓰면 416초(18%)로 줄고, 트랙 2,200~2,600 m 구간이 통째로 빠진다 [확인: 5-3절]. 차의 물리는 누가 몰든 같다 |
| 학습·검증·시험은 파일(주행) 단위로 무작위 배정한다. 14·3·3개, 배정 시드 0 | 창을 만든 뒤 섞어 나누면 겹치는 창이 양쪽에 들어가 점수가 부풀려진다. 시드 0은 석우 코드의 시드 번호(0, 1, 2)와 맞춘 것이다 |
| 5 m/s 이하 구간을 버리지 않는다 | 5 m/s 기준은 AV-21 데이터의 것이다. Golf에는 적용하지 않는다 |
| **[변경 11/18]** 단, 정지 구간(vx < 0.5 m/s)은 잘라 낸다 | 정지 중 기록된 제동력은 차를 붙잡아 두는 힘(중앙값 −3.1 kN)이라 움직임을 만드는 힘이 아니다. 물리 모델에 넣으면 "0 m/s에서 2 m/s² 감속"이 된다. 전체의 3.1%(144초)이고, 모두 파일 처음 0~26초와 2개 파일의 마지막 2초에 있다(달리다 서는 경우는 없음) [확인: 20개 파일]. 사용자 승인 |
| **[변경 11/18]** 출발 구간은 main에 남기고 구동력을 보정한다. 출발 구간 제외는 ablation으로 본다(10절) | 정지 구간을 빼도 출발 가속 부분(0.5→약 6 m/s)은 남는다. 64초, 전체의 2.7%, 20개 파일 모두 [확인]. 이때 클러치가 미끄러져(`clutchEngage_int` 0) 기어 맞춤 규칙으로는 구동력이 0이 되는데, 실제로는 2~4 m/s²로 가속한다 [확인: `2023-11.csv` 5.9~8.9초]. 사용자 제안·승인 |
| 시간 간격은 0.04초로 한다. 200 Hz 원본에 10 Hz 4차 버터워스 저역 통과 필터를 양방향으로 건 뒤 8개마다 하나씩 뽑는다. 시작 위치는 하나만 쓴다 | 0.04초면 MPPI 1초 계획이 25스텝으로 유지된다. 원본 간격(0.005초)을 그대로 쓰면 200스텝이 되어 계산량이 8배다. 모델이 쓰는 신호는 12.5 Hz보다 빠른 성분이 0.13% 이하라 필터로 잃는 것이 거의 없다 [확인: 5-4절]. 양방향 필터는 시간 지연을 만들지 않는다. 시작 위치 하나만 쓰는 것이 기존 코드와 가장 가깝다 |
| 타이어 온도는 main에서 쓰지 않는다 | 새 트랙에는 온도 기록이 없다. 모델 6개의 입력을 같게 유지한다. 온도는 ablation에서 다룬다(10절) |

### 4-2. 모델과 학습

| 결정 | 이유 |
|---|---|
| 모델은 ver2 `ladder_models/`의 R1–R6, 학습과 MPPI는 11/12 `share_source_team/src/`를 쓴다 | 회의 결정이다. ver2 모델 코드는 11/12 원본과 출력이 같다. IAC 체크포인트(R1–R6, 시드 0)를 양쪽에 넣어 1스텝·25스텝 출력 차이가 0임을 확인했다 [확인] |
| 종방향 입력은 force 방식으로 한다. 앞바퀴에 작용하는 앞뒤 방향 힘(N) 하나를 입력으로 쓴다 | ① Golf 데이터에 바퀴별 제동력이 N 단위로 있다. ② Golf는 기어가 바뀌어서 같은 스로틀에도 바퀴 힘이 달라진다. 스로틀 비율을 쓰는 pedal 방식은 R1의 구동 계수 한 벌로 설명하기 어렵다. ③ ver2에 이미 구현돼 있다 [확인: `ladder.py:118-128`]. ④ ver2의 가정이 Golf 데이터와 맞는다: 앞바퀴굴림, 앞 제동 몫 0.66(측정 ~~0.658~~ **[변경 11/19]** 0.75) [확인: 5-5절] |
| 구동력은 `GearRatio` 열을 쓰지 않고 실측 감속비로 계산한다 | `GearRatio` 열은 실제 감속비의 약 2.41배다. 그대로 쓰면 구동력이 23 kN으로 나와 실제 가속도와 맞지 않는다 [확인: 5-5절] |
| **[변경 11/18]** 구동계 효율 0.697을 입력 계산에 넣는다 (앞바퀴 힘 = 0.697 × 구동력 − 앞 제동력) | 12절의 "효율은 R1–R6이 학습으로 흡수한다"는 force 방식의 R1·R4에는 성립하지 않는다. 물리 식에 구동 이득 계수가 없어 질량으로 나눈 힘이 그대로 가속이 된다(`golf/ladder.py` `deriv`). 효율은 7절 방법으로 추정했다. 사용자 승인 |
| main 학습은 R1–R6 모두 1초 손실로 한다. 1스텝 손실은 ablation이다 | MPPI가 모델을 1초씩 굴려 쓰고, 개루프 평가도 1초 뒤 상태를 본다. 학습 목표와 쓰임이 같아진다. 1스텝으로 학습한 물리 모델은 타이어가 비현실적으로 약해졌다(최대 횡가속 0.35 g, 1초 손실은 1.75 g) [확인: `share_source_team/docs/iac_results.md:94`]. 모든 모델이 같은 손실을 써야 비교가 공정하다 |
| 학습 시드 0·1·2는 석우 코드를 따른다 | [확인: `iac_runall.sh`] |
| ~~에폭은 석우 코드를 따른다(1초 손실 40에폭·학습 창 절반, 1스텝 300에폭), 수렴 기준은 따로 두지 않는다~~ **[변경 11/18]** 모든 모델·모든 손실에 같은 규칙: 검증 손실이 10에폭 동안 0.1% 넘게 나아지지 않으면 학습률을 절반으로 줄이고, 25에폭 동안 나아지지 않으면 멈춘다. 최대 300에폭. 검증 손실이 가장 낮았던 에폭의 모델을 쓴다. 300에폭에 도달한 모델은 결과에 "최대 에폭 도달"로 표시한다 | 1단계 결과: R6는 40에폭에서도 검증 손실이 계속 내려가고 있었다(마지막 10% 구간에서 4~7%). 1스텝·300에폭으로 학습한 R5가 1초 예측에서도 1초·40에폭 R5보다 정확했다(1초 vx 오차 0.282 vs 0.479 m/s). 원래의 코사인 학습률은 끝에서 학습률이 0이 되어 손실 곡선이 저절로 평평해지므로, 곡선으로 수렴을 판단할 수 없었다. 모델마다 필요한 에폭이 달라 숫자를 하나로 정하는 대신 같은 멈춤 규칙을 쓴다(사용자와 논의). 최대 300은 시험 실행에서 R5가 300에폭까지도 조금씩 나아졌지만(마지막 100에폭 3~12%) 사용자가 유지하기로 했다 |
| **[변경 11/18]** 1초 손실도 학습 창을 전부 쓴다 | 2개 중 1개만 쓰면 두 손실의 비교에 "학습 데이터 양" 차이가 섞인다. 원래 이유는 시간 절약이었다. 사용자 선택 |

### 4-3. 제원 추정

| 결정 | 이유 |
|---|---|
| Golf 제원은 데이터로 추정한다 | 공개된 Golf 제원을 찾지 못했다. 파일 머리에는 차량 이름과 트랙 이름 두 줄뿐이다 [확인] |
| GTI와 AV-21 데이터를 `deep_dynamics/reference_vehicles/`에 두고 추정 방법을 검증하는 데 쓴다 | 다른 차의 데이터에서 Golf 제원이 나오지는 않는다. 제원을 아는 차에 같은 추정 방법을 돌려 아는 값이 나오면, 그 방법을 Golf에 믿고 쓸 수 있다 |
| BayesRace 데이터는 삭제한다 | 1:43 크기 소형 차의 시뮬레이션 데이터다. 실차가 아니라 검증에 쓸 수 없다 |
| 추정 방법은 관련 연구를 따른다(7절) | 사용자 결정 |
| **[변경 11/18]** 질량은 직진 제동 구간, 구동계 효율은 직진 구동 구간으로 나눠 추정한다(2단계). 무게중심 위치는 가정값(앞 무게 몫 0.61)을 쓴다 | 4개 계수 동시 회귀는 Golf에서 질량 490 kg, 효율 0.15처럼 물리적으로 맞지 않았다. 2단계 방법은 GTI 질량을 +5.3% 오차로 맞췄다(동시 회귀는 GTI에서 −0.2%). 무게중심 회귀는 GTI에서 −19.6%, AV-21에서 −52.2% 틀려 쓸 수 없었다 [확인: `experiments/golf/results/specs.md`]. 사용자 승인 |

### 4-4. 시뮬레이터

| 결정 | 이유 |

### 4-5. MPPI와 폐루프 실험

| 결정 | 이유 |
|---|---|
| 제어기는 MPPI, 계획 길이 1초로 고정한다(회의 결정) | 2초면 모든 모델이 완주해 차이가 사라진다. 이 프로젝트는 제어기 연구가 아니라 모델 비교다 |
| 새 트랙 주행은 A 방식과 B 방식을 모두 시험한다 | 지금 코드는 기록된 주행에서 경로와 목표 속도를 만든다 [확인: 9-1절]. 기록이 없는 트랙에서는 쓸 수 없다 |
| A 방식: 경로와 목표 속도를 계산으로 만들고 지금처럼 따라간다 | 모든 모델이 같은 기준을 받아 비교가 공정하다 |
| B 방식: 경로 없이 트랙 경계 안에서 최대한 전진한다. 계획 길이를 1, 2, 3, 4초로 바꿔 본다 | 1초만 내다보면 코너 앞에서 미리 감속하지 못한다. 최고 속도 32 m/s에서 15 m/s로 줄이려면 약 3.4초, 80 m가 필요하다(9-4절) |
| A 방식은 마찰 계수, 가감속 한계, 경로 세 요소를 grid search한다 | 세 요소가 목표 속도와 경로를 정한다 |
| grid search는 썬더힐에서 한다. 결과는 최적점을 고르지 않고 전체를 곡선으로 보고한다 | 최종 평가 트랙에서 탐색하면 시험 데이터로 튜닝하는 것과 같다. 모델마다 최적점을 고르면 모델별로 다르게 튜닝한 셈이 된다. "마찰 계수를 올릴수록 어느 모델이 먼저 실패하나" 곡선이 프로젝트 주장을 그대로 보여 준다 |

### 6-2. 종방향 입력 계산 (force 방식)

```
실측 감속비 = 엔진 회전 속도(rad/s) ÷ 앞바퀴 회전 속도(rad/s) → 가장 가까운 기어 값(8.8 / 5.65 / 3.93 / 3.0)
             어느 기어와도 10% 넘게 다르면 변속 중으로 보고 구동력 0
             [변경 11/18] 단, 1단보다 크면(출발 중 클러치 미끄러짐) 1단 감속비, 클러치 체결 1로 본다
구동력      = 엔진 토크 × 감속비 ÷ 바퀴 반지름(0.319 m) ~~× 클러치 체결 정도(clutchEngage_int ÷ 4)~~  [변경 11/19]
앞바퀴 힘   = [변경 11/18·11/19] 0.699 × 구동력 − (앞왼쪽 제동력 + 앞오른쪽 제동력)
```

**[변경 11/19] 클러치 신호를 곱하지 않는다.** 감속비가 기어 값에 맞으면 그대로 구동력으로 쓴다.
- **쉽게 말하면:** 엔진과 바퀴가 톱니바퀴처럼 정확한 비율(기어비)로 같이 돌고 있다면, 그 사이의 클러치는 붙어 있을 수밖에 없다. 클러치가 떨어져 있으면 엔진과 바퀴는 따로 돌아 비율이 맞지 않는다. 그래서 "비율이 맞는가"가 클러치 신호보다 확실한 증거다.
- **데이터 근거** [확인 11/19]: 10 m/s 이상·스로틀 30% 이상이면서 기어비가 맞는 표본 중, 클러치 신호가 0(=끊김)인 것이 약 15%였다. 이전 식은 이 순간의 구동력을 0으로 계산했다. 그런데 이 순간에도 차는 신호가 4(=체결)일 때와 거의 같은 엔진 토크로 거의 같게 가속했다.

  | 기어 | 클러치 신호 0 | 클러치 신호 4 |
  |---|---|---|
  | 1단 | 토크 216 Nm, 가속 2.2 m/s² | 231 Nm, 2.6 m/s² |
  | 2단 | 195 Nm, 0.95 m/s² | 198 Nm, 1.24 m/s² |

- 발견 경위: 시뮬레이터 재생에서 "앞바퀴 힘이 거의 0인데 차가 +0.35 m/s²로 가속하는" 표본을 추적하다 찾았다. 그 표본의 스로틀 평균이 65%였다.
- 기어비가 어느 기어와도 안 맞는 순간(실제 변속 중)은 여전히 0이다. 그때는 클러치가 정말 떨어져 있고(신호 0), 차도 감속한다(평균 −0.93 m/s²) [확인].
- 영향: 모든 모델의 입력이 바뀌므로 54개 모델을 다시 학습했다(`golf_results_phase1.md`).

- 뒷바퀴 제동력은 모델 안에서 앞 제동 몫으로 계산한다(`ladder.py:121-123`). Golf 데이터에는 뒷바퀴 제동력이 직접 있으므로, 설정의 앞 제동 몫을 측정값 ~~0.658~~ **[변경 11/19]** 0.75로 둔다.
- ~~구동계 효율은 위 식에 넣지 않았다.~~ **[변경 11/18]** 구동계 효율을 넣는다(4-2절, 7절). **[변경 11/19]** 값은 0.697 → 0.699(클러치 수정 뒤 재추정).
- 제동력 열(`brake_*_N`)은 양수로 기록돼 있다 [확인].

### 7-1. 방법 (관련 연구 기준)

| 대상 | 방법 |

### 8-1. CommonRoad 다물체 모델 [확인: 공식 문서 `vehicleModels_commonRoad.pdf`, 30쪽]

| 항목 | 내용 |
|---|---|
| 구조 | 질량 3개(스프링 위 질량, 앞·뒤 축의 스프링 아래 질량). 상태 변수 29개 |

| 빠진 것 | 조향계의 유연성, 범프 스톱, 서스펜션 기하에 의한 스쿼트·리프트 힘 |

### 8-2. 변환 단계

MPPI가 고른 조작을 시뮬레이터가 받는 형태로 바꾸는 단계다. 실제 차의 조향 모터, 엔진, 브레이크 역할을 한다.

| | MPPI가 내는 값 | 시뮬레이터로 넘기는 값 | 변환 |
|---|---|---|---|
| 조향 | 조향각 | 조향 속도 | (명령 조향각 − 현재 조향각) ÷ 0.04초. 지연을 넣는다 |
| 종방향 | 앞바퀴 힘 (N) | ~~바퀴 토크~~ **[변경 11/18]** 종방향 가속도 입력 | ~~앞바퀴 힘 × 바퀴 반지름을 엔진·브레이크 토크로 직접 넣는다.~~ **[변경 11/18]** 패키지는 입력 가속도 a를 엔진 토크 m·R_w·a(앞뒤 배분 `T_s,e`) 또는 브레이크 토크(`T_s,b`)로 바꾼다 [확인: `vehicle_dynamics_mb.py:334-347`]. 그래서 Fxf ≥ 0이면 a = Fxf / m(`T_s,e` = 1), Fxf < 0이면 a = Fxf / (0.75·m)(`T_s,b` = 0.75 **[변경 11/19, 이전 0.658]**, 나머지는 뒷바퀴 브레이크). 변환 전에 속도별 구동력 상한·제동 하한으로 자른다 |

- 기존 코드는 시뮬레이터를 `world(h)`로 부르고 `[vx, vy, r]`을 받는다(`iac_sim.py:189`). 같은 모양으로 감싸면 `episode()`를 크게 고치지 않아도 된다.
- R1–R6은 실제로 작용한 힘(이미 지연된 값)으로 학습한다. 지연은 변환 단계에만 넣는다. 모든 모델이 같은 지연을 겪으므로 비교는 공정하다.
- Golf에 맞출 것: 질량·관성·축 거리(7절), 타이어 배율 계수, 지연 값.

### 9-1. 현재 코드 [확인: `share_source_team/src/`]

- **목표 속도는 기록 기반이다.** 정해진 주행에서 평균 속도가 가장 빠른 한 바퀴를 고르고, 그 바퀴의 위치별 속도를 15칸 이동평균한 뒤 최저값을 8 m/s로 둔다(`iac_track.py:22-45, 87-91`). 마찰 계수나 가감속 한계는 쓰지 않는다.
- **경로는 그 바퀴에서 실제로 달린 선이다**(`iac_track.py:54-60`). 레이스라인을 계산하지 않는다.

- 정지 판정은 "차가 사실상 멈춰 주행에 실패했다"를 잡는 기준이라, 정상 주행에서 내려가지 않는 속도면 된다. 썬더힐 목표 속도 최저는 14.5 m/s, 실제 기록에서 한 번 10 m/s를 넘은 뒤 최저는 약 8.3 m/s다(주행을 끝내고 서는 경우 제외) [확인].
- AV-21 때의 이유(학습 범위 밖)는 Golf에서는 없다. main 데이터가 0.5 m/s까지 포함한다. 그래도 3 m/s 아래는 이미 실패라 결과가 같고, IAC와 비교할 수 있어 유지한다.
- 6 m/s는 출발 구간 ablation의 데이터 기준일 뿐이고, 출발 구간 ablation은 개루프 차이가 없어 main 설정으로 진행하므로 쓰지 않는다(사용자 검토).
- 비용의 "6 m/s 아래 벌점"은 실패 판정이 아니라 정지 전에 속도를 유지하게 하는 장치라 그대로 둔다.
- 정지 출발(시뮬레이터 검증의 기록 랩)에서는 한 번 10 m/s를 넘은 뒤부터 정지 판정을 적용한다(`episode(v_armed=10)`).

   | 조향 잡음 | 0.06 rad, 빠를수록 줄임 (유지) | 범위 대비 비율이 기존과 같다 |
   | 힘 변화 비용 가중치 | 5 × (1.7 / 13,000)² ≈ 8.6 × 10⁻⁸ | 단위가 뉴턴으로 바뀌어, 범위 비율로 환산해 기존과 같은 상대 크기로 맞춤 |

   정정: 11/18 논의 중 "구동력 표에 효율 0.697이 빠져 실제의 1.4배"라고 한 것은 잘못이었다. 표는 이미 `0.697 × F_drive`로 계산되어 있다(`drive_force_limit.py:17`).
2. **모델 중립 튜닝을 한다.**
   - 후보: λ {0.1, 0.3, 1.0} × 잡음 크기 배수 {0.5, 1, 2} = 9개 설정.

   - K는 1024로 고정한다.
3. B 방식은 비용이 다르므로 같은 절차로 따로 튜닝한다.
4. 튜닝은 썬더힐에서만 한다.
5. 9개 설정의 결과 표를 함께 남긴다.
6. **[변경 11/19] 튜닝 기준점**은 기록선 + **다른 실제 랩(`2023-10_5`, 108.2 s)의 위치별 기록 속도**로 하고, 그 랩의 실제 출발 위치에서 정지 출발한다(사용자 결정).

   - 시뮬레이터 검증 랩(`2023-10_8`)과 다른 랩이라 "기록에 맞춰 튜닝해 검증을 통과시키는" 순환을 피한다.

### 9-3. A 방식: 계산한 경로와 목표 속도를 따라간다

**목표 속도 계산:**
1. 위치마다 코너 한계 속도를 구한다: √(마찰 계수 × 중력가속도 ÷ 곡률).
2. 앞에서 뒤로 한 번 훑어 가속 한계를 넘지 않게 깎는다.
3. 뒤에서 앞으로 한 번 훑어 감속 한계를 넘지 않게 깎는다.

**grid:**

| 요소 | 값 | 개수 |
|---|---|---|
| 마찰 계수 | 1.2 × {0.8, 0.9, 1.0, 1.1, 1.2} = 0.96, 1.08, 1.20, 1.32, 1.44 | 5 |
| 가감속 한계 | (+4.3, −5.1 m/s²) × {0.8, 1.0, 1.2} | 3 |
| 경로 | 근사 경계의 가운데 선 / 곡률이 가장 작은 선 / 기록된 가장 빠른 주행선 | 3 |

- 기준값 1.2, +4.3, −5.1은 데이터에서 잰 값이다(5-5절).
- 45개 조합 × 모델 6개 × 시드 3개 = 810회.
- 줄이는 방법: 45개 조합은 시드 0 모델로만 돌리고(270회), 마찰 계수 곡선 하나(5개 조합)만 시드 3개로 돌린다.

### 구동력 상한

- **뜻:** MPPI가 후보 조작을 뽑을 때 앞바퀴 힘이 가질 수 있는 가장 큰 값, 즉 가속 쪽 한계다. 제동 쪽 한계(약 −6 kN)는 데이터에서 이미 읽었다.
- **필요한 이유:** MPPI는 정해진 입력 범위 안에서 무작위 후보를 만든다(`iac_sim.py:20-21`). 상한이 실제 엔진이 낼 수 있는 힘보다 크면, MPPI가 모델이 본 적 없는 힘으로 "가상의 급가속"을 계획한다. 그러면 결과가 데이터 밖 예측에 좌우된다. 실제 엔진은 속도가 높을수록 낼 수 있는 힘이 줄어들므로 상한은 속도에 따라 달라진다.
- **정하는 방법:** 20개 파일 전체에서 속도 구간별 최대 구동력(엔진 토크 × 실측 감속비 ÷ 바퀴 반지름)을 읽어 표로 만든다. 로더를 만든 뒤 계산한다.

### 구동계 효율

- **뜻:** 엔진이 낸 토크 중 변속기와 구동축의 마찰로 잃지 않고 바퀴까지 전달되는 비율이다. 승용차는 보통 0.9 안팎으로 알려져 있지만 Golf의 값은 모른다.
- **필요한 이유:** 6-2절의 식은 손실을 빼지 않아서 실제 바퀴 힘보다 크게 나온다. 가속 구간의 겉보기 질량이 제동 구간보다 크게 나온 원인 중 하나다(5-5절).
- **처리:** 효율이 일정한 배율이면 R1–R6이 학습으로 흡수할 수 있어 모델 비교에는 영향이 작다. 질량 추정과 시뮬레이터 변환 단계(힘 → 바퀴 토크)에는 값이 필요하다. 질량을 추정할 때 효율을 미지수로 함께 추정한다(7-1절).
