# 물리와 AI 팀 프로젝트 — 코드 확인용 컨텍스트 (2026-11-17 기준)

이 문서는 claude.ai에서 진행한 논의를 Claude Code로 넘기기 위한 것이다. 목표는 11/19(목) 팀 회의 전에 **소스 코드에서 사실을 확인**하는 것이다. 코드를 고치는 작업이 아니라 읽고 보고하는 작업이다.

---

## 0. 작업 방식

- **코드는 수정하지 않는다.** 읽기와 실행 확인만 한다. 수정이 필요해 보이면 제안으로만 남긴다.
- 답할 때는 근거가 된 **파일 경로와 줄 번호**를 함께 적는다.
- 코드에서 확인한 사실과 추측을 구분한다. 확인하지 못한 항목은 "확인 못 함"으로 남긴다.
- 보고는 한국어로 쓴다. 용어는 처음 나올 때 뜻을 풀어 쓰고, 번역투와 비문을 피한다. 사용자는 물리 비전공자다.

---

## 1. 프로젝트 한 줄 요약

신경망 차량 모델은 짧은 예측(개루프)에서 앞서지만, 한계 주행에서는 물리를 남긴 모델이 더 버틴다는 것을 보이는 프로젝트다. Thunderhill에서 수집한 VW Golf 한계 주행 데이터로 차량 모델 6종(R1–R6)을 학습하고, MPPI 제어기에 넣어 시뮬레이터에서 주행시켜 비교한다. 발표는 12/30이다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 한계 주행 | 타이어 접지력을 거의 다 쓰는 주행. 미끄러지기 직전이거나 이미 미끄러지는 상태 |
| 개루프 평가 | 기록된 데이터에서 모델이 다음 상태(예: 1초 뒤 속도·회전속도)를 얼마나 맞히는지 보는 평가 |
| 폐루프 평가 | 모델을 제어기에 넣고 시뮬레이터에서 차를 직접 몰게 해 완주 여부와 랩타임을 보는 평가 |
| MPPI | MPC(앞을 내다보며 조작을 정하는 제어) 방식 가운데 하나. 무작위 조작 후보를 많이 굴려 보고 비용이 낮은 쪽으로 조작을 정함 |
| 계획 길이 | MPPI가 몇 초 앞까지 내다보는지 |
| R1–R6 | 비교하는 차량 상태 예측 모델 6종. R1 순수 물리, R2–R5 물리+신경망 혼합, R6 순수 신경망 |

## 3. 확정된 팀 공통 결정

| 항목 | 결정 |
|---|---|
| 데이터 | https://purl.stanford.edu/hh613qz0317 의 Thunderhill VW Golf 실차 데이터. 이 링크가 기준이다 |
| 차량 상태 예측 모델 | share_source_team_ver2_models_only/ 디렉토리의 R1–R6 6종 |
| 제어기 | MPPI로 고정. 계획 길이 1초 (최종 결정) |
| 시뮬레이터 | 미정. **데이터셋 차량(Golf)과 일치**시켜야 함 |
| 트랙 | 마지막에 정함 |
| 평가 기준 | 1순위 완주 여부, 2순위 랩타임. 학습에 쓰지 않은 트랙에서도 검증 |

흐름: Golf 데이터로 R1–R6 학습 → MPPI가 각 모델로 1초 계획 → 시뮬레이터에서 주행 → 다른 트랙에서 일반화 성능 확인. 시뮬레이터 없이도 학습에 쓰지 않은 주행 기록으로 R1–R6 예측 오차는 비교할 수 있다.

결정 이유:
- 한계 주행 데이터가 필요하다. 지금까지 쓴 IAC(AV-21) 데이터와 bayesrace 데이터는 한계 주행이 아니다.
- 한 차량 데이터만 쓴다. 차마다 무게·크기·출력이 달라 섞으면 위험하다.
- MPPI를 1초로 고정한 이유: 2초면 모든 모델이 완주해 차이가 사라진다. 또 R4는 매 스텝 계수를 다시 추정하는 구조라 계획이 길수록 오차가 쌓여, MPPI 탓인지 모델 탓인지 가를 수 없다. 이 프로젝트는 제어기 연구가 아니라 모델 비교다.

### 차량 이름 구분 (중요)

- **Golf**: 이 프로젝트 데이터셋의 차량. 데이터셋 설명에 "fully autonomous VW Golf operating at the limits of its performance at Thunderhill Raceway Park"로 적혀 있다. 상태(RTK-GPS), 제어 입력, 액추에이터 상태, 실시간 타이어 온도를 포함한다.
- **GTI**: Spielberg 2019(Science Robotics) 논문의 차량. 같은 연구실·같은 트랙이지만 다른 차다.
- 데이터셋과 짝을 이루는 논문("Physics informed neural network vehicle model for highly dynamic automated driving", Mori et al.)은 웹에서 찾지 못했다.
- 팀원 정리에 "Stanford VW GTI", "시뮬레이터도 GTI에 맞춰야" 같은 표현이 있었는데, 기준은 Golf다.

## 4. 이전 실험에서 알려진 사실 (11/12, 11/17 회의)

- AV-21 데이터 로더가 5 m/s 이하 데이터를 버려 실제 데이터의 약 2/3을 잃었다. 구간별 수정으로 일부 복원했으나 경계값 처리 문제로 회전속도 오차가 늘었다.
- 무작위 분할이 시계열 데이터와 맞지 않지만, 고쳐도 성능 개선은 미미했다.
- 원본 논문 코드는 보고값을 재현하지 못했고, 원인은 아직 밝히지 못했다.
- 1초 뒤 상태 예측은 신경망이 앞섰지만, 실제 주행 시뮬레이션에서는 트랙마다 순위가 달랐다.
- MPPI 2초는 완주율이 오르지만 계산 시간이 늘어난다.
- Deep Dynamics 원본은 브레이크를 가속도의 음수로 단순화했으나, 석우는 브레이크를 별도 변수로 추가했다. 신경망 크기는 모델 간 동일하게 맞췄다.
- 목표 속도를 트랙 곡률만 보고 자동 계산한다는 설명이 있었다(석우). 팀원 정리에는 "기록된 가장 빠른 한 바퀴 속도"라고 되어 있다. **둘 중 무엇이 현재 코드인지 확인 필요.**
- Laguna Seca, Totsuka 등에서 물리·혼합 모델이 순수 물리 모델보다 헤어핀에서 나았다.
- 마찰 계수를 낮춘 실험에서 실패 27건 중 25건이 급코너 탈출 중 스핀·이탈이었다.
- 속도 배수를 1.3배 이상 올리면 모두 이탈했다.

## 5. 코드에서 확인할 것 (우선순위 순)

* 이때 코드는 deep-dynamics 디렉토리 뿐만이 아니라, share_source_team_ver2_models_only/ 디렉토리와 share_source_team/ 디렉토리를 포함한다.

### 5-1. MPPI 목표 속도 (회의 안건)

- [ ] 목표 속도 곡선을 어디서 만드는가? 기록 기반(가장 빠른 랩의 위치별 속도)인가, 곡률 기반(곡률과 마찰 계수로 위치별 한계 속도 계산)인가, 둘 다 있는가?
- [ ] 목표 속도는 위치별 곡선인가, 단일 값인가?
- [ ] 곡률 기반이라면 마찰 계수는 얼마로 가정하는가? 가감속 제한(속도 곡선 평활화)이 있는가?
- [ ] 속도 배수(1.3배 실험)는 어디서 곱하는가?
- [ ] 모든 모델이 같은 목표 속도를 받는가, 모델별로 다른가?
- [ ] 다른 트랙(기록 없음)에서 목표 속도를 어떻게 만드는가?

### 5-2. MPPI 비용 함수와 설정

- [ ] 비용 항목(레이스라인 이탈, 속도 오차, 조작 크기·변화량, 트랙 이탈 벌점 등)과 가중치
- [ ] 계획 길이 1초가 실제 코드값인지, 시간 간격(dt)과 스텝 수
- [ ] 샘플 수, 온도(λ) 등 주요 하이퍼파라미터
- [ ] 제어 입력이 무엇인가(조향, 스로틀, 브레이크 각각인지, 가속도 하나인지)

### 5-3. R1–R6 모델

- [ ] 각 모델의 구조를 한 줄씩 정리 (물리 부분과 신경망 부분이 각각 무엇을 맡는지)
- [ ] 입력 변수와 출력 변수 (브레이크 별도 변수 포함 여부)
- [ ] R1(순수 물리)이 쓰는 차량 모델 종류(자전거 모델인지, 타이어 모델은 무엇인지)와 차량 파라미터 값, 그 값의 출처
- [ ] R4의 "매 스텝 계수 재추정" 구조가 코드에서 어떻게 구현됐는지

### 5-4. 데이터 파이프라인

- [ ] 현재 로더가 AV-21 전용인지. Golf 데이터용 로더가 있는지
- [ ] Golf 데이터를 받았다면 파일 구성, 변수 목록, 샘플링 주기, 차량 제원(질량, 요 관성, 무게중심, 축거, 타이어 파라미터)이 들어 있는지
- [ ] 저속 필터, 분할 방식(무작위/시간순) 현재 상태

### 5-5. 현재 쓰는 시뮬레이터

- [ ] 지금까지 폐루프 주행(푸트남, 토트넘, Laguna Seca, Totsuka 등)을 무엇으로 돌렸는가? 시뮬레이터 안의 차량 모델은 무엇인가?
- [ ] **시뮬레이터의 차량 모델이 R1과 같은 식인가?** 같다면 R1이 구조적으로 유리하다 (6-1 참고)
- [ ] 마찰 계수 변경은 시뮬레이터 쪽에서 하는가, 모델 쪽에서 하는가?
- [ ] 트랙 파일의 출처와 형식(중심선, 트랙 폭, 레이스라인 포함 여부)

## 6. 시뮬레이터 조사 결과 (11/17 웹 조사)

### 6-1. 시뮬레이터 충실도가 결과를 바꾼다

Sagmeister et al., "Analyzing the Impact of Simulation Fidelity on the Evaluation of Autonomous Driving Motion Control" (TUM, AV-21 Monza 실주행 데이터로 검증, arXiv 2602.07984):
- 단일 트랙 모델과 선형 타이어 모델은 실제 데이터와 크게 어긋났고, 그 영향은 가속도가 클수록 지수적으로 커졌다. 저자들은 이런 단순 모델로 제어기를 평가하지 말라고 권한다.
- 한계 근처에서는 타이어 그립을 조금 바꾼 효과가 모든 모델 단순화의 효과보다 18배 넘게 컸다. 모든 효과를 넣는 것보다 파라미터를 정확히 맞추는 것이 중요하다.
- 하중 이동과 액추에이터 지연은 간단한 형태로라도 넣으라고 권한다.
- 타이어·서스펜션 파라미터를 구할 수 없어 실제 데이터에 맞춰 추정했다.

함의: 시뮬레이터가 R1과 같은 자전거 모델이면 R1이 유리해져 비교가 공정하지 않다. 시뮬레이터는 R1보다 충실도가 높아야 한다(4륜, Pacejka 타이어, 하중 이동, 액추에이터 지연). 타이어 파라미터는 Golf 데이터에 맞춘다.

### 6-2. 후보 모듈

| 후보 | 장점 | 걸리는 점 |
|---|---|---|
| CommonRoad Vehicle Models (`pip install commonroad-vehicle-models`) | Python. 운동학 단일 트랙~다물체 모델, Pacejka 단일 트랙 드리프트 모델 포함 | 다물체 모델 입력이 조향 속도·종방향 가속도라, 스로틀·브레이크를 쓰려면 구동·제동 모델을 붙여야 함 |
| Open Car Dynamics (github.com/TUMFTM/Open-Car-Dynamics) | C++ 다물체 모델. CommonRoad 기반에 Pacejka 2006, 타이어 지연, 서스펜션, 공기역학, 조향 액추에이터, 구동계 추가. 스로틀·브레이크 입력 | AV-21 파라미터는 기밀, 일반 레이스카 파라미터만 공개. ROS2/C++ 필요. Golf로 재파라미터화 필요 |
| sim_vehicle_dynamics (github.com/TUMFTM/sim_vehicle_dynamics) | 단일 트랙·4륜 모델, 구동계, 타이어 모델 | MATLAB 2018b/Simulink 필요 |

현민의 "알려진 모듈로 직접 구현" 제안에는 CommonRoad 다물체(또는 Pacejka 4륜) 모델에 간단한 구동·제동 모델을 붙이는 구성이 가장 가까워 보인다. 기존 코드가 Python이라면 붙이기 쉽다. **5-2의 제어 입력 형태와 5-5의 현재 시뮬레이터를 확인한 뒤 판단할 것.**

### 6-3. Golf 제원

공개된 Golf 제원은 찾지 못했다. 같은 연구실의 다른 시험 차량 값(예: Audi TTS 1500 kg / 2250 kg·m², 2018년 논문의 1659 kg / 2400 kg·m²)은 Golf에 쓰면 안 된다. 확보 순서: 데이터셋 파일 메타데이터 → 담당자 문의(dmori@stanford.edu) → 기본값은 일반 제원, 타이어는 데이터로 추정.

### 6-4. 타이어 온도

데이터에 타이어 온도가 있다. 같은 연구실 실험에서 주행이 길어질수록 타이어 온도가 오르고 마찰이 줄었다. 마찰 고정 시뮬레이터로 재생하면 랩 후반에 기록과 어긋날 수 있다. 학습·검증 분할 시 온도 분포도 확인할 것.

### 6-5. 트랙과 검증

- Thunderhill 레이스라인은 데이터의 GPS 궤적에서 만들 수 있다. 일반화용 트랙은 TUM racetrack-database(github.com/TUMFTM/racetrack-database, 중심선+트랙 폭, 주로 F1·DTM)를 쓸 수 있다. Thunderhill 포함 여부는 미확인.
- 시뮬레이터 검증: 학습에 쓰지 않은 구간의 기록된 조작을 시뮬레이터에 넣어 궤적을 비교한다. 한계 주행에서 긴 개루프 재생은 발산하므로 1–2초 단위 짧은 구간으로 나눠 비교한다.
