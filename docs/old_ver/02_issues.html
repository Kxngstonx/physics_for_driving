P1. AV-21 변환기가 로그의 첫 구간만 사용한다 심각도 높음 수정됨 · 3부

위치
deep_dynamics/tools/csv_parser.py:28-30, :81
원리
변환기는 속도가 5 m/s를 넘을 때까지 행을 건너뛰고 기록을 시작합니다. 그 뒤 속도가 처음으로 5 m/s 아래로 떨어지면 break로 파일 읽기를 끝냅니다. 피트 인이나 감속 뒤에 다시 달린 구간은 모두 버려집니다. 또한 인자로 CSV 한 개만 받고, train.py도 npz 한 개만 받습니다. 여러 로그를 합치는 수단이 없습니다.
결과
5개 CSV에서 5 m/s 이상인 행은 135,497개인데 변환기가 쓰는 행은 47,878개(35.3%)입니다. 한 번의 학습에는 그중 파일 하나만 들어갑니다.
수정 방향
break 대신 저속 구간을 경계로 세그먼트를 나누고, 세그먼트마다 윈도를 만든 뒤 여러 파일의 결과를 이어 붙입니다. 윈도가 세그먼트 경계를 넘지 않게 해야 합니다.

P2. 무작위 분할 때문에 검증과 테스트가 학습 데이터와 겹친다 심각도 높음 수정됨 · 3부

위치
deep_dynamics/model/models.py:40-43, train.py:139-141, evaluate.py:101-105
원리
윈도는 stride 1로 만들어져 이웃끼리 H−1 스텝을 공유합니다. split(0.8)은 이 윈도들을 시간 순서와 무관하게 random_split으로 나눕니다. 그러면 검증 윈도의 바로 앞이나 뒤 윈도가 학습셋에 들어갑니다. 80:20 무작위 분할에서 검증 윈도의 양옆 중 하나 이상이 학습셋에 있을 확률은 1 − 0.2² = 96%입니다. 윈도 i의 라벨은 윈도 i+1의 입력 안에 그대로 들어 있기도 합니다.
검증 영향
검증 손실이 일반화 성능이 아니라 학습 샘플 사이의 보간 성능에 가까워집니다. 가중치 저장 기준이 이 검증 손실이므로(train.py:89-90) 모델 선택도 같이 낙관적으로 치우칩니다.
테스트 영향
train.py는 테스트셋을 만들지 않습니다. evaluate.py는 넘겨받은 npz 전체를 평가합니다. README대로 학습에 쓴 파일을 그대로 넘기면 평가 샘플의 80%가 학습 샘플이고 나머지 20%도 위와 같이 겹칩니다. 경고는 나오지 않습니다.
정규화
StandardScaler가 분할 전에 전체 데이터로 fit됩니다(models.py:24-28). 검증 구간의 통계가 정규화에 섞이지만 위 문제에 비하면 영향은 작습니다.
수정 방향
시간 순서대로 블록을 나누고 블록 사이에 H 스텝 이상의 간격을 둡니다. 더 안전한 방법은 주행 로그 단위로 학습, 검증, 테스트를 나누는 것입니다. Scaler는 학습 구간으로만 fit합니다.

실험 전 권장 조치

  1. 변환기 수정 (P1). 저속 구간에서 멈추지 않고 세그먼트로 나누어 전부 변환하고, 여러 CSV를 한 데이터셋으로 합칩니다. 같은 김에 0으로 남는 마지막 5개 샘플을 없앱니다.
  2. 분할 방식 교체 (P2). 주행 로그 단위 또는 간격을 둔 시간 블록 단위로 학습·검증·테스트를 나누고, 테스트셋은 train.py가 접근하지 않는 별도 파일로 둡니다. Scaler는 학습 구간으로만 fit합니다.
  3. 기준선 입력 정리. Deep Pacejka IAC와 비교할 계획이면 VREF 열을 미래 vx가 아닌 값으로 바꾸거나 입력에서 뺍니다.
  4. 학습 루프 정리. 배치마다 hidden state를 0으로 초기화해 학습과 평가 조건을 맞추고, Ray Tune에는 검증 손실을 보고합니다.
  5. 재현성과 환경. 모델 생성 전에 시드를 고정하고, .cuda()를 .to(device)로 바꾸고, 절대 경로와 누락된 의존성을 정리합니다.
